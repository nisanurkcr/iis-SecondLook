What is this code trying to do?Find a user by name. The issue is how the entered name becomes part of the SQL query, not the lookup itself.


Prepared warning / 01Review input handling
Your input has a little too much power.
Potential SQL injection. The entered name is joined directly into the SQL query. Part of that input could be interpreted as database instructions.
find_user.py · lines 2–3 in the original example
Simulation note: this warning and the responses below are prewritten for this example. No AI model or scanner has analysed code.
In plain English
The name should be treated as data. Joining it into the query text mixes that data with the instructions the database reads.
What could go wrong?
A specially crafted value can change the meaning of the query, potentially returning records the user should not receive. The exact impact depends on the rest of the application.
Why suggest parameters?
In Python’s sqlite3 API, a ? placeholder and a separate parameter tuple let the database treat the name as a value rather than SQL syntax. This addresses the input handling shown here.
